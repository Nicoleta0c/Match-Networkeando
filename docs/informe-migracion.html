  • Probado con dos personas (el navegador y otra persona simulada con curl, cada una con su cookie): se ven entre sí y el match funcionó (96%). Un tercer perfil apareció solo en menos de 5 segundos. También probé borrar y los permisos 403 y 400.

3. Cómo correr la app

Para trabajar en ella (modo desarrollo)

cd "C:\Users\Analista BPA\networkeando-rd"
npm run dev

Abre http://localhost:3000. Para ver la demo: http://localhost:3000/#demo. Para pararla: Ctrl + C en la terminal.

Para el evento (los celulares se conectan por el mismo Wi-Fi)

  1. Si tienes npm run dev abierto, ciérralo primero, porque los dos usan el puerto 3000.
  2. Corre: 
    cd "C:\Users\Analista BPA\networkeando-rd"
npm run evento
  3. La primera vez, Windows pregunta si Node.js puede usar la red: marca Redes privadas y acepta. Si no aceptas, los celulares no podrán entrar.
  4. En la laptop abre http://localhost:3000/#proyectar y toca "Pantalla completa". El QR ya apunta a tu laptop.
  5. Prueba primero con tu celular: escanea el QR y crea un perfil.
  6. Durante el evento, no cierres la terminal ni dejes que la laptop se duerma (conéctala a la corriente).
Ojo con el Wi-Fi: muchas redes de invitados o corporativas tienen "aislamiento de clientes" y no dejan que un celular vea a la laptop. Si pasa, usa un router normal o el hotspot de un celular. La IP de la laptop cambia según la red; el QR la actualiza solo cuando abres #proyectar.

Para activar la IA

Abre .env.local, pega tu clave después de ANTHROPIC_API_KEY= y vuelve a arrancar la app. Sin clave, todo funciona con el método básico.

Para empezar un evento desde cero

Para la app, borra prisma\dev.db y corre npx prisma migrate dev. Ahora mismo la base está vacía: borré los perfiles que creé para las pruebas.

4. Hosting gratuito con SQLite (sin publicar nada todavía)

SQLite guarda todo en un archivo, así que necesitas un hosting con disco permanente. Si el disco se borra en cada reinicio, se pierden los perfiles. Estos planes cambian seguido: confirma precios y límites en cada página antes de decidir.

Tu laptop en el Wi-Fi del eventoSíSí, tal como estáLo que ya tienes. No necesita cuenta ni cambios. Solo funciona dentro del lugar.
Turso + VercelTienen plan gratisSí: Turso es SQLite en la nube (libSQL)Vercel no guarda archivos, así que la base iría en Turso. Hay que agregar el adaptador de Prisma para libSQL y cambiar la conexión. Es un cambio pequeño.

Mi recomendación: para un evento presencial, usa tu laptop (npm run evento): es gratis, ya funciona y los datos se quedan contigo. Si después quieres que la app viva en internet, la opción gratuita más sólida es Vercel + Turso, pero necesita ese cambio pequeño en la conexión a la base. 5. Cosas que conviene saber

  • Sin probar con celulares reales. Probé entrando por la IP desde la misma laptop. La prueba final es escanear el QR con tu celular en el Wi-Fi del evento. Tampoco pude leer el QR con un programa (no se permitió cargar código externo en la página), así que confirma con la cámara que abre la dirección correcta.
  • IA en la demo: al entrar a #demo, la primera búsqueda puede empezar antes de saber si hay IA y usar el método básico; "Buscar de nuevo" ya usa la IA. El original tenía el mismo comportamiento.
  • Aviso de npm audit: 3 avisos "high" en deepmerge-ts, que usa la herramienta de línea de comandos de Prisma 6 (no la app que ven los usuarios). Se arregla subiendo a Prisma 7, que es un cambio grande. Lo dejé así a propósito.
  • CLAUDE.md todavía describe el plan viejo (Firebase/Supabase). Conviene actualizarlo para que futuras sesiones de Claude Code no se confundan.
  • El círculo con una "N" abajo a la izquierda solo aparece en modo desarrollo (es la herramienta de Next.js). En npm run evento no sale.
  • Next.js creó solo un archivo AGENTS.md con notas para asistentes de IA. Es normal.
